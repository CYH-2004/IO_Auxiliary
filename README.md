# IO_Auxiliary

IO_Auxiliary是一个基于MCU实现的IO辅助控制器，可实现更加灵活的IO拓展。

## 项目说明

* 这是什么？

  这是一个基于单片机的IO拓展方案，目前采用STC32G12K系列单片机实现，已支持GPIO拓展、PWM输出等功能。

* 它能做什么？

  目前功能还比较少，只支持通过IIC接口拓展两路PWM输出和两个GPIO，而且PWM只有占空比实时可调，频率暂时需要在源码中改。

* 怎么想到做这个？

  这个辅助控制器的方案其实是本人前一个项目的衍生品。当时主控是ESP32，IO不是很够用，必须增加拓展芯片。但一般方案难以实现同时拓展PWM输出和普通IO。正好对STC的单片机比较熟悉，就考虑采用一片较小封装的单片机通过软件实现IO拓展。实际测试后效果还算比较满意，目前做类似方案的似乎也比较少，于是整理了一下开源。

* 用这个方案实现IO拓展相比传统方案有什么优缺点？

  优点：IO拓展更加灵活，轻松集成PWM输出、ADC测量、定时控制等功能，还可支持数据保存；
  缺点：成本略高、功耗较高、存在响应延迟、需要烧录。

* 这个拓展IO的方案成本大概多少？

  目前使用的STC32G12K64-TSSOP20，官方零售价2.1元/PCS，成本会比使用传统芯片高一些。不过目前这个型号其实是性能严重过剩的（个人开发当然上最好的型号啦），需要成本控制的话可以考虑用STC8H系列的小容量型号，引脚兼容；或者换用STC8051U-34K64-LQFP48，这个型号48脚的封装零售价也只要1.9元/PCS，应该是按IO数量平均下来最便宜的了，不过软件可能不完全兼容。

* 这个项目可以移植到其他单片机上吗？

  可以，但需要对单片机的寄存器操作有所了解。目前源码是纯C语言编写的，使用keil c251编译，对于STC的改进型C251内核单片机移植比较容易，换一下不同型号的头文件再根据具体型号微调一下寄存器和时钟配置应该就行了。但对于STM32等cortex-m系列内核的单片机，改动就会稍微多一点，主要是硬件IIC的中断处理相关内容需要调整，需要比较熟悉寄存器操作。不过移植到STM32F103或者更高级的型号上面除非是个人学习，不然也没什么实际意义啊，成本要爆炸了。

* 后续会更新什么？

  目前的计划主要是加上休眠与唤醒，然后调整一下程序架构，实现完整的IO读写、PWM输出、ADC检测等拓展功能。以后也可能考虑移植到CH32V003上。
  非常欢迎大家参与这个项目的开发呀，复杂度不高，但一个人精力有限，推进比较缓慢。用单片机做IO拓展这个方案我觉得还是比较有价值的，效果还算不错的同时成本可控，目前貌似也很少类似的开源方案。另外大家如果有什么想法的话也请务必积极提出哦。

## 版本说明

* v1.7B
  1. 支持主机使用最高400kHz的IIC接口访问IO_Auxiliary从设备，默认7位地址0x2A；
  2. 支持使用4个普通IO，可实时配置为高阻输入、推挽输出、开漏输出、准双向口；
  3. 支持两路占空比可调的PWM输出；
  4. 支持进入睡眠模式以降低功耗，可通过单独的INT引脚唤醒；
  5. 支持读取32位的固件版本ID。
